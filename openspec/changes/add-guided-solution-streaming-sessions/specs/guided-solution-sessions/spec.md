# Spec Delta

## Purpose

为登录后的师生提供一个受班级边界保护、可连续追问且可回看的解题助手，让教师配置的提示词和解题引导技能与本班知识检索共同参与每轮回答，并以流式事件及时呈现结果。

## ADDED Requirements

### Requirement: 班级助手提示词可由教师维护

系统 MUST 为每个班级保存一份当前生效的助手提示词；教师可以创建或更新该提示词，学生不得创建、修改、删除或通过普通问答接口取得管理凭据。提示词 MUST 只描述助手身份、回答边界和表达约束，不得替代本课的解题引导技能。保存成功后，后续新发送的消息 MUST 使用新提示词，已完成的消息内容不得被静默改写。

#### Scenario: 教师更新提示词后下一轮生效
- **WHEN** A 班教师提交有效提示词并随后在 A 班会话中发送问题
- **THEN** 助手请求使用最新提示词生成该轮回答
- **AND** B 班回答仍使用 B 班自己的提示词

#### Scenario: 学生不能修改班级提示词
- **WHEN** A 班学生调用提示词管理接口或提交伪造的教师身份
- **THEN** 接口返回 HTTP 403
- **AND** 已保存提示词保持不变

### Requirement: 解题引导技能可启用并限制回答方式

系统 MUST 为每个班级提供至少一个名为“解题引导”的技能。教师可以启用或停用该技能，学生不能改变开关。技能启用时，命中依据的回答 MUST 给出解题思路、步骤或检查方向，引用本班材料标题与切片位置，并 MUST NOT 直接给出题目的最终答案；技能停用时，同一问题的回答方式 MUST 与启用时有可观察差异，但仍受提示词、知识库依据和引用规则约束。

#### Scenario: 启用解题引导只给思路
- **WHEN** 教师启用 A 班的“解题引导”技能且学生提问命中本班材料
- **THEN** 回答包含可执行的思路或步骤及材料引用
- **AND** 回答不直接给出最终答案

#### Scenario: 学生不能切换技能
- **WHEN** 学生在创建会话或发送消息时提交技能开关参数
- **THEN** 服务端忽略该参数或返回 HTTP 403
- **AND** 实际开关值仍来自教师保存的班级配置

### Requirement: 会话与消息按用户和班级持久化隔离

系统 MUST 允许已登录用户创建会话、列出自己有权查看的会话、读取会话消息并连续发送问题。每个会话和消息 MUST 关联创建者的用户 ID 与其登录时的班级；用户不得读取、追加或删除其他用户或其他班级的会话。会话消息至少保存角色、文本、创建时间、回答状态和引用元数据；服务重启后已完成的会话仍可读取。

#### Scenario: 学生连续追问
- **WHEN** 学生创建会话，发送第一条问题并在同一会话发送第二条追问
- **THEN** 第二轮可以使用该会话中先前的用户/助手消息作为上下文
- **AND** 每轮回答分别保存并返回各自的引用

#### Scenario: 跨用户或跨班访问被拒绝
- **WHEN** A 班学生使用合法 Bearer Token 访问 B 班或另一用户的会话 ID
- **THEN** 接口返回 HTTP 404 或现有统一的不可见资源响应
- **AND** 响应不泄露会话标题、消息、班级或材料信息

### Requirement: 每轮回答按固定助手链路执行

系统 MUST 在接受一条会话问题后，按以下可观察顺序完成处理：确认 Bearer 身份与会话归属，读取班级提示词，读取教师配置的技能开关，使用本轮最新问题检索当前班级知识库，再生成回答。历史消息仅作为上下文，客户端提交的 system/developer 消息、class_id、技能配置、向量分数和其他班级内容 MUST 被丢弃。检索最多提供 4 个切片给回答模块；没有命中时 MUST 返回固定的未找到说明和空引用，不得调用回答模型。

#### Scenario: 一次回答同时使用提示词、技能和本班依据
- **WHEN** 已登录学生在 A 班会话发送命中 A 班材料的问题
- **THEN** 服务端使用 A 班当前提示词、技能规则和最多 4 个 A 班切片生成回答
- **AND** 返回的每个引用都能定位到 A 班材料标题、切片序号和原文

#### Scenario: 没有依据时拒答且不调用模型
- **WHEN** 当前班级检索不到会话问题的任何切片
- **THEN** 回答为固定的“资料中未找到相关内容”类消息，引用为空
- **AND** 服务端不调用回答模型且不生成臆造出处

### Requirement: 会话回答通过 SSE 增量返回

系统 MUST 提供登录保护的会话消息流式接口。接口响应 MUST 使用 `text/event-stream`，按顺序发送可解析的事件，至少包含开始、一个或多个文本增量、完成或错误事件；完成事件 MUST 包含持久化消息 ID、最终回答文本和按 `[1]` 等编号对应的引用。事件流结束后，消息和引用 MUST 已持久化；客户端断开连接时服务端 MUST 停止继续向该连接写入，并将消息标记为可识别的失败或中断状态。

#### Scenario: 客户端逐段看到回答
- **WHEN** 学生向自己的会话发送有效问题且检索命中材料
- **THEN** 浏览器收到 `text/event-stream` 响应并在收到增量事件时逐段显示回答
- **AND** 最终事件包含与正文引用编号一致的来源列表

#### Scenario: 流式生成失败可识别
- **WHEN** 回答服务在流式过程中不可用或返回无效内容
- **THEN** 服务发送错误事件并以非成功状态标记该消息
- **AND** 错误内容不包含 API 密钥、内部请求体或其他班级材料

### Requirement: 助手工作区支持连续会话与状态反馈

登录后的工作区 MUST 能新建会话、选择已有自己的会话、发送问题并逐段显示回答；页面 MUST 显示正常流式回答、无依据、回答服务失败、认证失效和会话不可见等状态。回答与引用正文 MUST 以纯文本安全渲染，页面不得直接访问 Qdrant、嵌入服务或回答网关。教师可从工作区进入提示词和技能管理入口，学生看不到可编辑控件但仍受服务端权限保护。

#### Scenario: 学生在工作区完成一次流式提问
- **WHEN** 学生登录后新建会话并提交一个命中本班材料的问题
- **THEN** 页面逐段显示 SSE 回答、最终引用和会话消息状态
- **AND** 页面不展示提示词/技能编辑控件，也不向浏览器暴露模型或向量服务地址

#### Scenario: 页面恢复历史会话
- **WHEN** 用户刷新工作区并选择自己之前完成的会话
- **THEN** 页面显示已持久化的问题、回答和引用顺序
- **AND** 不显示其他用户或其他班级的会话
