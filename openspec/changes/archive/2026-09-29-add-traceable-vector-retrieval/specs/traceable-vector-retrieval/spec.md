# Spec Delta

## Purpose

让教师和学生能够在当前班级的材料中进行可解释的关键词、向量或混合检索，并将命中切片追溯到原文；在有可靠依据时生成带引用的简短回答，在没有依据时明确拒答而不编造来源。

## ADDED Requirements

### Requirement: 材料正文切片与索引

系统 MUST 将每条已入库材料正文切分为带材料标识、切片序号、字符区间和切片正文的知识切片。上传和显式重建索引 MUST 使用同一套选定策略；未指定策略时 MUST 使用 `auto`。系统 MUST 支持 `auto`、`custom` 和 `hierarchy` 三种策略：`auto` 最大约 800 个字符、重叠约 80 个字符并优先在自然断点切分；`custom` 接受 100 至 2000 个字符的长度和 0% 至 50% 的重叠；`hierarchy` 按 Markdown 标题分章，过长章节再按窗口切分。预处理不得改写权威材料正文。

#### Scenario: 上传正文生成可定位切片
- **WHEN** 教师上传有效的 `.txt` 或 `.md` 材料且正文入库成功
- **THEN** 系统生成一个或多个有序切片
- **AND** 每个切片的序号、字符区间和 `chunk_text` 能定位回该材料的原始正文

#### Scenario: 按指定策略重建索引
- **WHEN** 教师或受保护的维护流程使用 `custom` 或 `hierarchy` 为某材料重建索引
- **THEN** 旧切片及其向量被替换为本次策略生成的切片
- **AND** 原始材料正文保持不变

#### Scenario: 重建索引幂等
- **WHEN** 对同一材料使用相同策略重复重建索引
- **THEN** 系统不会产生重复切片、重复向量或不可追溯的旧主键

### Requirement: 三种检索模式

系统 MUST 提供登录保护的知识检索接口，支持 `mode=keyword`、`mode=vector` 和 `mode=hybrid`，默认模式 MUST 为 `hybrid`。`keyword` MUST 只使用关系库全文索引，不调用嵌入服务或向量库；`vector` MUST 将查询转换为向量并按余弦相似度检索；`hybrid` MUST 同时执行两路并按各自名次使用 RRF（`k=60`）融合，缺席的一路不贡献名次分。向量候选相似度低于 `0.35` MUST 被过滤。检索结果 MUST 有数量上限，且不得用明显低相关候选凑满上限。

#### Scenario: 关键词模式只命中原文词
- **WHEN** 已登录用户以 `mode=keyword` 查询一个出现在本班正文中的词
- **THEN** 系统按全文相关度返回匹配切片
- **AND** 该请求不需要查询向量或访问向量服务

#### Scenario: 向量模式命中语义相近表达
- **WHEN** 已登录用户以 `mode=vector` 查询与本班正文含义相近但未复用主要原词的表达
- **THEN** 系统返回相似度不低于 `0.35` 的本班切片
- **AND** 每条结果均可回表取得原文摘录

#### Scenario: 混合模式按名次融合
- **WHEN** 已登录用户以默认 `mode=hybrid` 查询
- **THEN** 关键词路径和向量路径分别过滤、排序后再使用 RRF（`k=60`）融合
- **AND** 两路都命中的切片优先于只命中一路的同等候选

#### Scenario: 向量服务故障不伪造结果
- **WHEN** 向量服务不可用且用户请求 `mode=vector` 或 `mode=hybrid`
- **THEN** 接口返回 HTTP 503 和可理解的错误信息
- **AND** 系统不得伪造向量分数或把关键词结果冒充为向量/混合结果

#### Scenario: 空查询被拒绝
- **WHEN** 用户提交空白查询
- **THEN** 接口返回 HTTP 400
- **AND** 系统不访问全文索引、嵌入服务或向量库

### Requirement: 班级范围严格取自会话

所有检索路径和回表查询 MUST 使用认证会话中的 `class_id`。查询字符串、JSON 正文、请求头或向量过滤中的客户端班级编号 MUST 被忽略或拒绝，且不得覆盖会话值。跨班检索对外 MUST 表现为 HTTP 200 的空命中集合或固定未找到提示，不得通过 403/404 暗示他班材料存在。

#### Scenario: 关键词检索不可跨班
- **WHEN** A 班用户使用仅出现在 B 班正文中的词进行关键词检索
- **THEN** 响应为 HTTP 200 且 `hits` 为空，或返回固定的未找到提示
- **AND** 响应不包含 B 班的标题、正文、材料 ID 或切片 ID

#### Scenario: 向量检索双侧过滤
- **WHEN** A 班用户提交向量或混合查询，并在请求中伪造 B 班 `class_id`
- **THEN** 向量候选与关系库回表均只使用会话班级 A
- **AND** 结果中不得出现 B 班切片

#### Scenario: 未登录用户不能检索
- **WHEN** 未登录用户请求任一检索模式
- **THEN** 接口返回现有 API 约定的 HTTP 401
- **AND** 不返回任何命中内容

### Requirement: 结果可追溯到关系库原文

每条命中 MUST 返回材料标题、材料 ID、切片序号、字符起止区间、原文摘录和可访问的受保护材料入口。摘录 MUST 来自关系库保存的 `chunk_text`，而不是向量库 payload。向量库 payload MUST 只保存必要标识，不得成为客户端获取正文的入口。跨班或已删除来源按现有材料资源规则拒绝，且不得泄露元数据。

#### Scenario: 命中结果带出处
- **WHEN** 检索返回一个切片
- **THEN** 响应包含标题、切片序号、字符区间和与原文一致的摘录
- **AND** 用户可打开当前会话有权访问的材料预览或下载入口

#### Scenario: 删除来源后旧结果失效
- **WHEN** 材料被删除后用户使用旧切片或材料 ID 访问来源
- **THEN** 来源访问按不存在资源处理
- **AND** 后续检索不再返回该切片

### Requirement: 无依据时明确未找到

当所选检索模式过滤后没有候选切片时，系统 MUST 返回 HTTP 200、空的 `hits` 和固定可理解的未找到消息（例如“资料中未找到相关内容”）。系统 MUST NOT 以低相关切片凑数，也 MUST NOT 在该路径调用回答生成模型。

#### Scenario: 本班没有依据
- **WHEN** 用户查询与当前班级材料无关
- **THEN** 检索响应为 HTTP 200，`hits` 为空并包含固定未找到消息
- **AND** 响应不包含其他班级的候选

### Requirement: 有依据后生成带引用的简短回答

系统 MUST 提供受保护的 `POST /api/ask`。接口只使用本轮最新问题发起本班混合检索，最多取前 4 个切片；历史对话可作为上下文，但客户端提供的 `system` 消息 MUST 被丢弃。只有检索到切片后，系统才可调用服务端回答网关。回答中的 `[1]`、`[2]` 等编号 MUST 与返回的 `citations` 顺序一致，回答网关不得获得向量分量、Qdrant 原始点数据或其他班级内容。本课不要求流式输出。

#### Scenario: 有依据时回答并标注引用
- **WHEN** 用户提问命中本班至少一个切片
- **THEN** 系统将最多 4 个切片及标题、序号和正文交给回答模块
- **AND** 响应包含简短回答和按 `[1]` 等编号排列的 citations，编号顺序与出处列表一致

#### Scenario: 无依据时不调用回答模型
- **WHEN** `/api/ask` 的混合检索没有命中切片
- **THEN** 接口返回固定未找到回答和空 `citations`
- **AND** 系统不调用回答网关

### Requirement: 索引故障可识别并恢复

材料原文成功持久化后，切片或嵌入失败 MUST 保留材料和可识别的失败状态，不得写入不完整的向量记录。系统 MUST 提供受保护的重建流程，能够删除旧切片/向量并按新策略重建；应用和 Compose 重启后已成功建立的索引 MUST 仍可检索。关键词检索在向量服务不可用时仍 MUST 可用。

#### Scenario: 嵌入失败保留原文
- **WHEN** 材料保存成功但嵌入网关失败
- **THEN** 材料和切片正文仍存在，切片状态标记为失败
- **AND** Qdrant 中不存在对应的不完整向量点

#### Scenario: 重建恢复失败索引
- **WHEN** 管理流程对失败材料执行重建且依赖恢复
- **THEN** 旧失败切片和向量被清理后生成可检索的新索引
- **AND** 关键词、向量和混合模式按成功状态返回结果

#### Scenario: 重启后索引持久
- **WHEN** 应用和 Compose 服务重启
- **THEN** 已成功索引的材料无需重新上传即可检索
- **AND** Qdrant 不对浏览器暴露端口或管理接口

### Requirement: 工作区提供检索与引用反馈

已登录教师和学生 MUST 能在材料工作区输入问题、选择三种检索模式并查看命中切片、出处和回答状态。界面 MUST 区分正常结果、无依据、向量服务不可用和回答失败；正文和摘录 MUST 按纯文本安全展示。学生仍只能检索，上传入口继续受服务端教师权限保护。

#### Scenario: 工作区展示混合检索结果
- **WHEN** 用户提交有效问题
- **THEN** 页面展示命中切片的材料标题、序号、摘录和打开材料入口
- **AND** 页面不直接访问 Qdrant 或模型网关

#### Scenario: 工作区明确显示无依据
- **WHEN** 查询没有本班命中
- **THEN** 页面显示固定未找到提示且不显示虚假的相关切片或引用
