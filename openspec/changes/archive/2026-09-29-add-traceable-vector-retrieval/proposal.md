# Proposal

## Why

第 3 课已经把材料保存到受班级隔离保护的知识库，但用户只能按材料标题定位内容，无法用自然语言找到正文依据，也无法确认检索结果来自哪一个原文切片。第 4 课需要在现有登录和材料能力之后补上可追溯的关键词、向量和混合检索，并在有依据时生成带引用的简短回答。

## What Changes

- 将已入库正文按可配置策略切分为带序号和字符区间的 `knowledge_chunks`，支持自动窗口、自定义分隔符和 Markdown 标题层级三种策略。
- 提供 `keyword`、`vector`、`hybrid` 三种检索模式，默认使用混合检索；关键词与向量路径均按会话班级过滤，混合结果使用 RRF（k=60）融合。
- 使用关系库保存切片正文与全文索引，使用服务端 Qdrant 集合保存向量和标识；向量主键与切片主键一致，向量库不重复保存正文。
- 增加可追溯检索 API 和工作区展示：结果返回材料标题、切片序号、字符区间、原文摘录及受保护的材料入口；低于向量阈值 0.35 的候选不计入结果，空结果返回固定的未找到提示。
- 增加 `/api/ask` 简短问答流程：仅在本班混合检索命中切片后调用服务端回答网关，并按检索结果顺序生成 `[1]` 等引用；无命中时不调用模型且 citations 为空。
- 增加索引重建、失败状态恢复、材料删除清理和 Compose 中 Qdrant 数据持久化；浏览器只访问本站 API，不暴露 Qdrant、嵌入网关或回答网关。

## Capabilities

### New Capabilities

- `traceable-vector-retrieval`: 覆盖切分、三种检索模式、班级范围、来源追溯和有依据的引用问答。

### Modified Capabilities

无。第 3 课的认证、角色、上传和材料授权保持既有契约；本 change 在其上新增检索能力。

## Impact

影响 Flask API、SQLite 知识库 schema、材料上传/删除流程、前端工作区、Docker Compose 服务和测试。为贴合现有工程，SQLite 继续承担当前关系库职责，Qdrant 通过 Compose 作为向量服务；嵌入与回答采用可配置的服务端网关适配器，密钥不进入浏览器。既有 `/api/materials` 标题筛选、`.txt`/`.md` 上传和班级隔离行为必须保持兼容。
