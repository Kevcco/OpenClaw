# Spec Delta

## Purpose

为教学助手和知识检索建立最小化且可追溯的运行审计，使管理员能还原某次处理选用了哪些技能、命中了哪些材料切片以及哪些命中形成引用，同时不暴露原文正文、密钥或跨班数据给师生。

## ADDED Requirements

### Requirement: 检索与回答命中必须持久化为审计轨迹

系统 MUST 为每次 `/api/knowledge/search` 检索、兼容的 `/api/ask` 单次问答和会话消息回答创建唯一审计标识，并持久化操作类型、认证用户、认证班级、时间、处理状态、技能候选/匹配/加载决定及版本，以及每个检索命中的材料标识、标题快照、切片标识、排名、检索模式/分数和是否被最终回答引用。无命中及回答失败的操作也 MUST 保存对应状态。知识检索响应 MUST 返回审计标识；单次问答响应 MUST 返回审计标识；会话 SSE 的开始或完成事件 MUST 返回审计标识。审计数据 MUST 在服务及 Compose 重启后保留，且不得复制知识切片正文、向量 payload、回答全文、认证 Token 或模型密钥。

#### Scenario: 审计知识检索命中
- **WHEN** 已登录用户执行本班检索并得到一个或多个切片
- **THEN** 系统为此次检索持久化每个命中的来源快照、排名、分数/模式和审计状态
- **AND** 检索响应包含可用于定位该轨迹的审计标识

#### Scenario: 审计一次助手回答及其引用
- **WHEN** `/api/ask` 或会话消息检索本班证据并生成回答
- **THEN** 一条审计轨迹关联本轮技能判定、版本、全部命中和最终引用编号
- **AND** 单次问答响应或 SSE 事件返回同一审计标识

#### Scenario: 无命中或回答故障仍可追溯
- **WHEN** 检索无命中、技能预算排除匹配技能或回答服务失败
- **THEN** 审计记录保存无命中/跳过/失败状态及可用的技能决定
- **AND** 记录不伪造来源、不保存密钥或完整回答正文

#### Scenario: 审计数据随服务重启保留
- **WHEN** SQLite/Compose 应用重启后管理员查询既有审计标识
- **THEN** 对应技能版本、来源命中、引用关系和处理状态仍可读取
- **AND** 该记录不含被引用切片的正文内容

### Requirement: 仅受信任授予的管理员可分页查询审计

系统 MUST 提供受 Bearer 身份保护、支持审计标识及班级/用户/时间/技能/来源/状态筛选和有界分页的管理员审计查询。管理员资格 MUST 由仅可通过受信任部署或数据库管理流程操作的服务端授权记录决定；HTTP 客户端提交的 role、class_id、用户名或管理员标志 MUST NOT 授予权限。普通教师和学生 MUST 收到 HTTP 403，且不得跨班查询审计。审计响应只返回重建处理轨迹所需的标识、时间、状态、技能信息和来源元数据，不返回切片正文、完整提示词、完整回答、Token、API 密钥或向量服务原始载荷。

#### Scenario: 授权管理员按审计标识查询
- **WHEN** 已获可信服务端授权的管理员用有效 Bearer Token 请求一条审计记录
- **THEN** 服务端返回该记录的技能决定、版本、检索命中、引用关联和状态
- **AND** 管理员可用有界分页和支持的筛选条件查询其他记录

#### Scenario: 教师或学生不能查看全局审计
- **WHEN** 普通教师或学生请求管理员审计 API，即使伪造 role、class_id 或管理员字段
- **THEN** 服务端返回 HTTP 403
- **AND** 响应不包含任何审计标识是否存在、来源或其他班级信息

#### Scenario: 审计响应进行内容最小化
- **WHEN** 管理员读取包含知识命中的审计记录
- **THEN** 响应包含可辨认的来源标题、材料/切片标识和命中/引用关系
- **AND** 响应不包含切片正文、回答全文、提示词全文或任何服务密钥
