# Spec Delta

## Purpose

让教学助手从单个固定技能扩展为由服务端可信技能包驱动的注册表，同时保留教师按班启停能力，并以适用条件和指令预算控制每轮回答实际加载的完整技能内容。

## ADDED Requirements

### Requirement: 技能以可信文件夹包注册

系统 MUST 从部署端只读的技能目录加载教学技能包。每个技能包 MUST 包含机器可读元数据、简短说明、适用条件、版本、优先级、完整指令文件和完整指令的 token 成本声明；脚本目录可以为空或包含可选资源。注册表 MUST 为每个技能提供唯一稳定标识，并在元数据缺失、路径越界、标识重复或指令文件无效时拒绝注册该包。教师和学生的请求 MUST NOT 创建、覆盖或执行技能文件、指令或脚本。

#### Scenario: 注册有效的技能包
- **WHEN** 服务启动时发现包含有效元数据、指令文件和唯一标识的部署技能包
- **THEN** 系统将其作为可信注册技能提供给班级配置和回答编排
- **AND** 技能版本及其完整指令成本可被服务端读取

#### Scenario: 拒绝不可信或冲突的技能包
- **WHEN** 技能目录中的包引用目录外文件、缺少必需字段或与其他包使用相同标识
- **THEN** 系统拒绝该包并记录不含密钥或指令正文的诊断
- **AND** 客户端提交的同名技能、指令或脚本不会改变注册表

#### Scenario: 包内脚本不会被请求执行
- **WHEN** 技能包包含可选脚本，或用户在提示中要求执行脚本
- **THEN** 系统仅将脚本作为已登记资源，不执行脚本、Shell 命令或外部工具调用

### Requirement: 教学技能按统一格式注册

系统 MUST 使用同一种技能包格式注册“解题引导”“错题讲解”和“作业批改”。现有各班“解题引导”启用状态 MUST 在迁移中保留；新增加的“错题讲解”和“作业批改”在每个班级 MUST 默认关闭。新技能的启用只改变是否可参与后续回答，不得新增作业提交、成绩保存或自动执行脚本等流程。

#### Scenario: 迁移已有解题引导设置
- **WHEN** 系统初始化包含现有班级技能配置的数据库
- **THEN** 各班已有“解题引导”的启用/停用状态保持不变
- **AND** “错题讲解”和“作业批改”各有一条默认关闭的班级设置

#### Scenario: 注册技能保持统一的外部行为
- **WHEN** 教师查看本班技能列表
- **THEN** 三项技能均以稳定标识、名称、说明、版本及本班启用状态展示
- **AND** 技能内容仍由部署端注册包决定，而不是由班级请求写入

### Requirement: 教师仅能管理本班已注册技能的开关

系统 MUST 提供教师可读取本班注册技能清单并启用或停用本班技能的工作区入口和受 Bearer 保护的 API。每次状态修改 MUST 增加班级设置版本。教师 MUST NOT 修改技能包元数据、适用条件、指令、优先级或脚本；学生对任何技能管理读取或写入请求 MUST 得到 HTTP 403。服务器 MUST 从认证身份取得班级，忽略或拒绝请求中伪造的班级编号。现有“解题引导”设置入口 MUST 保持兼容，且映射到注册表中的同一技能设置。

#### Scenario: 教师启停本班已注册技能
- **WHEN** A 班教师启用或停用一个已注册技能
- **THEN** 只有 A 班该技能的启用状态和设置版本发生变化
- **AND** 后续新回答读取更新后的状态

#### Scenario: 学生或伪造班级不能改技能
- **WHEN** 学生请求技能管理接口，或教师在请求中提交其他班级的 class_id
- **THEN** 学生收到 HTTP 403，且服务端不会接受伪造班级来定位配置
- **AND** 未授权或其他班级的设置保持不变

#### Scenario: 技能指令不属于班级更新接口
- **WHEN** 教师提交启用状态之外的指令、元数据或脚本字段
- **THEN** 服务端拒绝这些字段或忽略它们
- **AND** 注册包内容及其版本不会被该请求修改

### Requirement: 按适用条件和预算渐进披露技能

每轮助手回答 MUST 只将当前班级已启用技能的一句话说明作为常驻技能上下文。服务端 MUST 根据本轮问题与注册包的机器可读适用条件确定匹配技能，不匹配的技能 MUST NOT 注入完整指令。匹配技能 MUST 按包内优先级从高到低、稳定标识升序的顺序选择；其完整指令的声明 token 成本总和 MUST 不超过部署配置的技能指令 token 预算。预算不足时 MUST 跳过不能完整装入的指令而非截断指令；已有系统提示词和检索证据不得被技能内容挤出或改变。

#### Scenario: 只向回答上下文加载匹配的启用技能
- **WHEN** 学生的问题匹配本班一个已启用技能的适用条件，但不匹配其他技能
- **THEN** 回答上下文包含已启用技能的一句话说明和该匹配技能的完整指令
- **AND** 不包含未匹配或已停用技能的完整指令

#### Scenario: 多技能选择遵循确定的顺序和预算
- **WHEN** 一条问题匹配多个已启用技能且所有指令成本超过预算
- **THEN** 系统依优先级和稳定标识顺序加载可完整容纳的指令
- **AND** 未能完整容纳的技能不会被截断后注入

#### Scenario: 没有技能条件匹配
- **WHEN** 问题不匹配任何本班已启用技能的适用条件
- **THEN** 回答上下文不包含任何完整技能指令
- **AND** 既有的提示词、知识检索、来源引用和无依据拒答规则仍适用
