# Proposal

## Why

当前“解题引导”以班级配置和服务端固定指令实现，新增教学能力会继续增加特例；同时会话只保存最终引用，无法解释哪些启用技能被选择、检索命中了哪些切片。需要先建立可扩展、可审计的技能基础，再逐步扩展教学智能体能力。

## What Changes

- 将教学技能定义为服务端可信的文件夹包，包含机器可读元数据、指令正文和可选脚本；以唯一技能注册表发现和校验包，不允许学生或教师通过普通请求提交可执行代码，包内脚本在本变更中仅登记而不执行。
- 将现有“解题引导”迁移为首个技能包，并以同一格式注册默认关闭的“错题讲解”和“作业批改”技能包；教师只能管理本班已注册技能的启用状态，不能改变身份、适用条件、指令或脚本。
- 按渐进式披露加载技能：回答上下文只带已启用技能的一句话简介；服务端依据包中机器可读的适用条件确定候选技能，按优先级在配置的 token 预算内加载完整指令，未匹配或超出预算的技能不注入。
- 持久化每次知识检索及单次/会话问答的技能判定与选择、技能版本、检索命中切片标识/名次/分数、最终引用及状态；响应提供审计标识，并提供仅管理员可用、支持分页筛选的审计查询，不返回 API 密钥或向量正文载荷。
- 管理员身份由受信任的部署/数据库管理流程授予和撤销，不新增客户端自报角色或公开提权 API；学生和教师不能跨班查看审计记录，技能启停和权限判断仍完全由服务端强制执行。
- 本变更建立文件格式、注册表、启用配置、渐进加载和审计闭环；技能脚本只作为受信任包内的可选资源登记，本变更不开放任意脚本执行、Shell/MCP 或模型工具调用。

## Capabilities

### New Capabilities

- `teaching-agent-skill-registry`: 文件夹化技能包、可信注册表、班级启用状态、适用条件选择和预算约束下的渐进式披露。
- `assistant-audit-trail`: 对技能选择和知识检索命中留痕，并由管理员安全查询特定回答的运行轨迹。

### Modified Capabilities

- `traceable-vector-retrieval`: 会话和单次问答记录每次命中切片，并将完整检索轨迹与最终引用关联。

## Impact

预计影响 `app/db.py`、助手/检索路由与回答编排、技能包目录和加载器、教师技能设置 UI、管理员身份/审计 API、OpenAPI/Swagger、SQLite 迁移、pytest 与 `apitest/`。需兼容已有提示词、解题引导班级开关、会话历史和 `/api/ask`；不得要求删除现有数据库或知识索引。部署方通过受数据库文件访问控制保护的管理命令授予或撤销审计管理员，普通 HTTP API 不提供提权入口。
