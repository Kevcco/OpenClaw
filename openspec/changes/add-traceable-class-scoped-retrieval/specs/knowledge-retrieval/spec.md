# Spec Delta

## Purpose

让教师和学生能够在当前班级的教研材料中按知识内容进行混合检索，并通过准确的命中片段和来源位置核验、打开原始材料。

## ADDED Requirements

### Requirement: 班级范围内的混合知识检索

系统 MUST 为已登录教师和学生提供知识库检索。检索 MUST 同时利用关键词匹配与语义相似度信号，并返回按综合相关性排序的有限结果集合。检索范围 MUST 由服务端从当前会话取得的班级决定；请求中的 `class_id` MUST NOT 扩大或改变检索范围。每条结果 MUST 包含可读的命中片段及来源信息。

#### Scenario: 通过正文关键词检索本班材料
- **WHEN** 班级 A 的用户提交一个出现在 A 班材料正文但未出现在标题中的关键词
- **THEN** 检索结果包含该正文命中的材料和对应片段
- **AND** 返回集合中的每条来源均属于班级 A

#### Scenario: 通过语义相近表达检索本班材料
- **WHEN** 班级 A 的用户提交与 A 班材料表达含义相近、但没有共享主要关键词的查询
- **THEN** 综合检索结果能够返回语义相关的本班材料片段
- **AND** 结果中仍提供可核验的原文片段和来源

#### Scenario: 伪造班级参数不能扩大检索范围
- **WHEN** 班级 A 的用户在检索请求中指定班级 B 的 `class_id`
- **THEN** 系统忽略该参数或拒绝请求
- **AND** 响应不得包含班级 B 的标题、片段、材料标识或来源信息

#### Scenario: 空白查询被拒绝
- **WHEN** 用户提交空白查询
- **THEN** 系统返回明确的客户端输入错误且不执行跨班或全库检索

#### Scenario: 无匹配内容返回空结果
- **WHEN** 用户提交有效查询但当前班级没有匹配内容
- **THEN** 系统返回成功响应和空结果集合

#### Scenario: 未登录用户不能检索
- **WHEN** 未登录用户请求知识库检索
- **THEN** 系统按受保护 API 的既有约定拒绝请求
- **AND** 响应不得包含任何材料或知识片段

### Requirement: 检索命中可追溯到原始材料

每条检索结果 MUST 携带原始材料标识和标题、材料内可定位的位置以及从原文截取的命中片段。用户 MUST 能从结果打开对应材料的受保护预览或下载；来源材料不存在、已删除或不属于当前用户班级时，访问 MUST 按现有材料授权约定拒绝且不得泄露其内容或元数据。界面 MUST 将命中内容呈现为安全文本，不得执行材料中的 HTML 或脚本。

#### Scenario: 结果提供可核验的来源定位
- **WHEN** 检索命中某材料的一个内容片段
- **THEN** 结果包含该材料的 ID、当前标题、片段在材料中的稳定位置及与原文一致的命中片段
- **AND** 用户可从该结果打开同一材料的受保护预览或下载原文件

#### Scenario: 删除或越班来源不可通过旧检索结果访问
- **WHEN** 用户访问已删除材料的旧结果来源，或尝试访问其他班级的材料来源
- **THEN** 系统拒绝材料访问并返回与现有材料接口一致的未找到响应
- **AND** 响应不暴露材料标题、正文、文件路径或班级归属

### Requirement: 知识内容索引保持与材料一致

系统 MUST 将已入库材料内容建立为可检索的片段，并为每个片段保留关联材料、班级和来源定位。现存知识库材料 MUST 可通过可重复执行的初始化或重建流程纳入索引；新上传材料在被报告为可检索后 MUST 可被本班检索命中。材料删除后，其片段 MUST 不再出现在检索结果中。索引数据 MUST 在应用重启后保持可用，索引失败 MUST 可被识别和恢复，不能静默造成永久漏检或返回失效来源。

#### Scenario: 上传材料完成索引后可被检索
- **WHEN** 教师成功上传受支持的 `.txt` 或 `.md` 材料且索引处理完成
- **THEN** 同班教师和学生均可按材料正文检索到该材料
- **AND** 其他班级用户检索不到该材料及其内容

#### Scenario: 已有材料可以补建索引
- **WHEN** 系统首次启用检索或执行索引重建
- **THEN** 既有知识库材料被纳入检索索引
- **AND** 重复执行重建不会产生重复结果或重复来源记录

#### Scenario: 材料删除后清除可检索片段
- **WHEN** 有权教师删除本班材料
- **THEN** 该材料关联的检索片段不再出现在后续检索结果中
- **AND** 其他材料的检索记录保持可用

#### Scenario: 索引故障可恢复
- **WHEN** 材料已持久化但某次索引写入或更新失败
- **THEN** 系统记录可识别的未完成索引状态或失败信息
- **AND** 后续重试或重建能够恢复该材料的检索能力，且不会留下不可追溯的孤立结果

#### Scenario: 应用重启后索引仍可用
- **WHEN** 已索引材料所在的应用或 Compose 服务重启
- **THEN** 用户无需重新上传材料即可检索到重启前的内容

### Requirement: 工作区展示知识检索结果

已登录教师和学生 MUST 能在现有材料工作区发起内容检索，并查看有限数量的相关结果、命中片段和来源入口。界面 MUST 区分加载失败、无结果和正常结果状态。现有按标题筛选材料的接口行为 MUST 保持兼容；知识内容检索不得要求用户获得超出其当前班级的访问权限。

#### Scenario: 用户从工作区查看内容检索结果
- **WHEN** 已登录用户在工作区提交有效查询
- **THEN** 工作区展示当前班级的相关材料片段及来源入口
- **AND** 用户打开结果后可在安全预览中核验该材料内容

#### Scenario: 无结果和检索错误有明确反馈
- **WHEN** 用户查询在本班没有匹配项，或检索服务暂时失败
- **THEN** 工作区分别显示无匹配提示或可理解的错误提示
- **AND** 错误时不以无结果状态掩盖索引失败
