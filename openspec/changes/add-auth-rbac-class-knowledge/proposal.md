# Proposal

## Why

CampusClaw 面向中小学教研场景，教研材料与知识库是后续学情分析、备课和教研协同的基础。当前材料分散在群文件与网盘中，教师难以复用，班级之间也缺少明确的数据边界，因此需要先建立身份、角色、班级隔离和可验收的材料入库能力。

## What Changes

- **用户登录**：教师、学生两类角色使用账号密码登录；未登录访问受保护页面时引导至登录页。
- **角色权限**：教师可上传和管理本班材料；学生仅可查看本班材料，调用上传接口必须被拒绝。
- **班级隔离**：班级是数据边界；所有业务查询在服务端按会话中的班级过滤，A 班用户不得读取、修改或删除 B 班材料。
- **材料上传与知识库入库**：教师上传的材料落盘、解析并写入知识库；材料关联本班，本班材料列表从数据库查询且上传后可见新记录。
- **预置核心数据**：建立班级、用户、讲义、作业、助手、技能等核心结构；预置 A/B 两班、教师 A、学生 A1/B1 及两班可区分的材料。
- **安全与运行**：密码仅以哈希存储；会话签名密钥仅由服务端环境变量注入；使用 Docker Compose 启动，提供无需登录的 `GET /health`，并持久化数据库和上传目录。
- **文档**：README 保留价值、场景和非目标说明；Apply 阶段补充 Docker 启动步骤、登录地址和健康检查地址。

## Capabilities

### New Capabilities

- `auth-upload`: 覆盖登录与会话、角色授权、班级隔离、教师上传材料入库、预置数据、密码与密钥安全、Docker Compose 和健康检查等可验收行为。

### Modified Capabilities

无。`openspec/specs/` 当前没有主规格。

## Impact

- Apply 阶段将新增 Web 页面与 API：登录、登出、材料列表、按 ID 访问、教师上传和健康检查。
- Apply 阶段将新增 SQLite 持久层、种子脚本、上传目录及知识库条目，并建立班级、用户、讲义、作业、助手、技能等数据结构。
- 项目将增加 Python/Flask 依赖、应用入口、`Dockerfile`、`docker-compose.yml` 与 `.env.example`。
- 本 change 当前只交付规划文档；实现工作严格按 `tasks.md` 在 Apply 阶段完成。

## Non-goals（非目标）

- 不做 RAG、全文检索、智能问答或基于知识库的对话。
- 不做聊天界面、Agent 编排、技能包运行时或技能开关。
- 不做作业提交、批改、成绩、审计或错题本。
- 不做注册、找回密码、多校多租户、OAuth/OIDC、SSO 或短信/邮箱验证码登录。
- 不做 Kubernetes、多副本高可用或完整 CI/CD；本地和课堂演示环境以 Docker Compose 为标准启动方式。
- 不以隐藏按钮或禁用表单替代服务端角色权限和班级隔离。
